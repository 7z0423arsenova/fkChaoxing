# fkChaoxing 桌面版使用教程

桌面程序用 MyGo 显示窗口，用 Rust 核心登录学习通并处理课程任务。窗口支持首次配置、读取课程、选择课程、启动或停止任务，以及单题查询。下方步骤以项目根目录为起点。

## 1. 安装语言工具与桌面组件

从源码运行需要 Rust 1.85+、Go 1.27.3+ 和系统 WebView。先按[安装教程](../docs/install.md)完成对应系统的安装，并运行 `rustc --version`、`cargo --version`、`go version` 检查。已有构建好的桌面包时不需要安装 Rust 和 Go。

## 2. 构建并启动

安装完成后，先编译 Rust 核心，再启动窗口：

```sh
cargo build
cd desktop
go run .
```

Windows PowerShell 中执行相同命令。`cargo build` 会生成 `target/debug/fkChaoxing.exe`，桌面程序会查找这个文件。以上命令中的 `cd desktop` 很重要，开发模式会从该目录查找 Rust 核心。

想构建本机安装包，在 Linux 或 macOS 的项目根目录运行：

```sh
sh desktop/build-local.sh
```

构建结果在 `desktop/build/`。Linux x86-64 的归档和 `.deb` 位于 `desktop/build/linux-amd64/`；归档解压后可运行其中的 `fkchaoxing`。应用显示名为 `fkChaoxing`，MyGo 要求 Linux 可执行文件和安装包名称使用小写。macOS 请打开构建产物中的应用。修改桌面页面或 Go 代码后，要重新运行构建命令并退出旧窗口，再打开新程序；已经打开的窗口仍使用旧页面。Windows 也有 [CI 构建流程](../.github/workflows/main.yml)；自行构建时，在项目根目录用 PowerShell 运行：

```powershell
cargo build --release --locked
New-Item -ItemType Directory -Force desktop/resources/windows-amd64/bin | Out-Null
Copy-Item target/release/fkChaoxing.exe desktop/resources/windows-amd64/bin/fkChaoxing-core.exe
cd desktop
go run github.com/egoist/mygo/cmd/mygo build
```

各平台都需要对应平台的 Rust 核心，单独复制桌面程序无法运行课程任务。

## 3. 首次配置

首次打开时填写学习通账号和密码，点击“保存配置并继续”。课程 ID 可以留空；读取课程后可直接勾选。学习设置默认视频倍速为 `1`，同时处理 `4` 个章节。这里的数字是并发章节数，不是线程数；一个章节里的任务点仍按顺序处理。

题库可以先不启用。选择“言溪题库”时需要 Token；“GO题”可以直接选，授权 Token 可留空；“自定义 AI 接口”需要 API 地址、Key 和模型名。勾选“启用 AI 回退”后，程序会先查主题库，没命中时再查 AI；AI 的 API 地址、Key、模型名由你自己填写，也可以填服务商预设（例如 `ollama`、`lmstudio`）后把 API 地址留空。勾选“自动提交章节检测答案”后，程序会按题库覆盖率决定是否提交，不能保证答案正确。默认不提交，最低覆盖率默认是 `0.8`，可在“自动提交最低覆盖率”中调整，也可在配置文件中修改 `cover_rate`。

向导把 `config.ini` 写到 MyGo 的用户数据目录，保存后窗口会显示实际路径。账号、密码和 API Key 以明文写入该文件；不要把文件发给他人或提交到仓库。已有配置可点“选择文件”直接打开，所选路径下次启动会恢复。向导不会覆盖已经存在的配置文件。

要修改已有配置，点击路径旁的“编辑配置”，在表单中修改后点“保存修改”。从项目根目录启动时，如果该目录有 `config.ini`，窗口会自动选中它。密码、题库 Token 和 API Key 在表单中不回显；留空会保留文件里的原值。表单没有提供的配置项也会保留。可以勾选“优先使用已保存的 Cookie”；Cookie 失效时仍需账号和密码才能重新登录。

如需手动修改配置，可参考项目根目录的 [精简模板](../template.ini)。修改后重新读取课程或重新启动任务，新配置才会用于新进程。桌面版的 Cookie 和 `fkChaoxing.log` 也在 MyGo 用户数据目录；命令行版使用终端当前目录。新版默认数据目录名为 `fkChaoxing`；已有 `Chaoxing` 数据目录且尚无新目录时会继续使用旧目录，保留配置与登录会话。

## 4. 读取并选择课程

配置表单的“学习设置”提供“启用章节检测答题”开关，首次配置和编辑已有配置均可修改，默认开启。取消勾选并保存后，下一次学习会跳过章节检测答题和大模型连接检查，继续处理视频等任务。原有题库设置会保留，随时可以重新开启；“自动提交章节检测答案”仍单独控制是否提交。跳过的检测任务不会因此在学习通上标记完成，单独的“题库测试”仍可使用。

同一区域还有“后台预取答题”开关，默认关闭。开启后，视频等任务运行时会提前查询本章后续章节检测答案并写入缓存，轮到检测时直接使用，可减少等待时间；代价是会提前消耗题库或 AI 请求次数。预取只改变查询时机，不改变是否提交。

同一区域还有“自动识别图片验证码（ddddocr）”开关，默认关闭。开启前需要在本机安装 Python 与 ddddocr（`python -m pip install ddddocr`）；桌面版会调用 `python3` 或 `python`，也可以用 `config.ini` 的 `[captcha] python` 指定解释器。它只处理学习通的图片字符验证码，滑块、人脸等验证仍需在浏览器完成。

点击“读取课程”，窗口会登录并列出当前账号的课程。每项下面显示“课程 ID”和“班级 ID”，例如：

```text
课程 123456789 · 班级 987654321
示例课程
```

上例中的 **`123456789` 是课程 ID**，`987654321` 是班级 ID。窗口按课程 ID 合并同一课程的多个班级；勾选一个课程时会处理该课程 ID 对应的班级。每次读取课程后，列表默认不勾选。请勾选要学习的课程，或点“全选课程”，然后点击“开始学习”。

左侧课程卡片显示每门课程的完成章节数和状态；右侧状态栏只有一个主按钮，运行时变为“停止”。运行日志按章节折叠，展开后可看到每道题的答案来源、是否命中以及警告；顶部标签可以只看警告和错误，或只看随机兜底。反馈问题时，请附上日志区底部列出的完整日志文件。再次运行前先检查日志，确认上次任务已经结束。`config.ini` 中的 `course_list` 是可选的默认课程列表，但窗口启动任务时会使用当前勾选的课程 ID。

运行时，日志上方为每个媒体任务显示独立进度条，章节学习次数也使用独立进度条。进度在原位置刷新，完成后移除并保留一条完成记录；停止任务会清空仍在运行的进度条。下方仍显示任务开始、章节完成、警告和错误。

## 5. 测试题库

先在配置向导或 `config.ini` 中启用题库。展开页面底部的“题库测试”，选题型、输入题目；选择题的选项每行写一个。点击“查询答案”只查询这一题，不启动课程任务。默认直接查询题库；勾选“使用本地答案缓存”后才会读取缓存。

桌面窗口没有手动输入答案的交互界面，因此不要把 `provider` 设为 `TikuManual`。需要手动答题时请使用[命令行教程](../docs/cli.md)。

## 6. 常见问题

- **找不到 Rust 核心**：先在项目根目录运行 `cargo build`，再从 `desktop` 目录运行 `go run .`；打包时确认 Rust 核心在对应平台的资源目录。
- **读取课程失败或 Cookie 过期**：检查配置路径和账号密码。桌面版的 `cookies.txt` 保存在 MyGo 用户数据目录；账号登录成功后会重新保存会话。
- **课程列表里有两个数字**：选择“课程 ID”，不要把班级 ID 填到 `course_list`。
- **章节检测跳过**：确认题库已启用并填写了所需 Token 或 API 信息。没有题库时程序会跳过需要答题的任务点。
- **视频出现 `媒体状态异常: "waiting"`**：这是媒体接口返回的状态，日志本身不能判断是限流还是播放速度造成的。先在学习通确认该视频可播放，检查有无验证码或任务点限制，再尝试把倍速设为 `1`、并发章节数设为 `1` 后重试。
- **提示媒体验证拦截或服务器未确认章节完成**：程序会停止或将该章节标为失败。请在课程网页检查验证要求和未完成任务点；完成状态以网页显示为准。重试时可先把倍速和并发章节数都设为 `1`。

目前自动测试覆盖本地模拟接口与桌面桥接；真实账号和课程仍需在你的环境中验证。命令行用法见[命令行教程](../docs/cli.md)。
